# План программы: квантово-гравитационный S-matrix bootstrap
*Самодостаточный документ для внешней проверки. 2026-08-13. ScienceBro / Andrey Pluzhnik.*

## 0. Контекст: кто мы и что уже есть

Один исследователь (ORCID 0009-0005-5660-2603) + ИИ-агент (Claude) на одной Windows-машине
(CPU-класс, RTX 4070 бесполезна для float64). За плечами — завершённый проект: независимый
аудит нейросетевого поиска чёрных дыр (AInstein, arXiv:2607.05489), опубликованный с DOI
(10.5281/zenodo.21915627, github.com/AndreiPLK/spacetime-verifier). Из него у нас есть
работающая дисциплина: proof-gates (статусы считаются из хешированных артефактов, ИИ не может
заверить свою работу), заморозка порогов до просмотра результатов, сохранение провалов,
известные-ответы-тесты, изоляция проверяемого кода. Портфолио: andreiplk.github.io.

## 1. Новая цель (North Star, неизменяемая)

**Вопрос:** в рамках явно указанных предположений (причинность, унитарность, аналитичность,
кроссинг, локальность — каждый результат перечисляет свой точный набор) — вынуждены ли
согласованные гравитационные амплитуды быть струнными, и какие предположения для этого
минимально необходимы?
**Метод:** S-matrix bootstrap — выводить свойства амплитуд рассеяния гравитонов из одних
принципов непротиворечивости (причинность, унитарность, аналитичность, кроссинг,
локальность), без предположения о струнах.
**Валюта результата:** теоремы, строгие границы, контрпримеры, новые допустимые семейства
амплитуд, карты «какие предположения необходимы».
**Не является целью:** платформа, аудиты чужих статей, обработка каталогов.

## 3. Что скачиваем/устанавливаем (полный список, всё бесплатно)

**Литература (день 1):**
- PDF трёх якорных статей + их ключевые prerequisite-цитаты (arXiv, sha256 в corpus.jsonl)
- API-доступы (без ключей или бесплатные): arXiv API, INSPIRE-HEP API, Semantic Scholar API —
  для «радара новизны» (проверка: не сделано ли уже то, что мы «нашли»)

**Инструменты (ставим по мере необходимости, не заранее):**
| Инструмент | Назначение | Когда |
|---|---|---|
| SymPy (есть) | символьные выкладки | день 1 |
| mpmath (есть в deps) | высокоточная арифметика (проверка чисел независимо) | день 3 |
| python-flint (Arb) | ИНТЕРВАЛЬНАЯ арифметика — сертифицированные числа: результат = интервал, гарантированно содержащий истину | день 3–4 |
| SciPy + CVXPY/HiGHS | линейное/выпуклое программирование (ядро численного бутстрапа) | день 4–5 |
| Lean 4 + Mathlib + lean-lsp | машинная проверка доказательств: Lean физически не принимает неверный вывод | неделя 2 |
| SDPB | полуопределённая оптимизация | только если микропроблема потребует |
| PySR / ShinkaEvolve | поиск компактных законов / эволюционный перебор кандидатов | только при детерминированном оценщике |

Правило: не ставить два инструмента на одну работу без измеренной причины.
**Жёсткий бюджет: ≤20% времени на инфраструктуру, ≥80% на физику.** Любой новый tooling
обязан быть затребован активной научной задачей, а не «пригодится».

## 4. Архитектура защиты от ошибок ИИ (строится ДО первых утверждений)

Каждое утверждение имеет ровно один статус:
`IDEA → NUMERICALLY_SUPPORTED → ANALYTICALLY_PROVED → FORMALLY_VERIFIED → PHYSICALLY_REVIEWED`

Повышение статуса — только через 4 замка (расширение нашего проверенного proof-gate):
1. **Численный замок:** независимая реализация без общего кода + интервальная арифметика
   (Arb) + случайные/граничные/асимптотические тесты
2. **Адверсариальный замок:** активный поиск контрпримеров ДО попытки доказательства;
   несколько независимых подходов, а не защита одного ответа
3. **Формальный замок:** Lean-проверка доказательства (машина, не LLM, судит вывод)
4. **Новизна+смысл:** радар по arXiv/INSPIRE/Semantic Scholar (не переоткрыли ли известное) +
   позже физик-рецензент

Все провалы сохраняются; пороги и критерии успеха замораживаются в git до просмотра
результатов; LLM никогда не единственный оценщик.

## 5. План по времени

**День 1–2 — фиксация и чтение**
- NORTH_STAR.md в репо + обязательное правило перечитывания в CLAUDE.md
- Архивация (не удаление) AInstein-специфики; перенос переиспользуемого (proof-gates, evidence)
- Полное чтение трёх якорных статей → **3 карточки микропроблем**, каждая: точная
  математическая формулировка / что известно / подозреваемая дыра / детерминированный
  проверятель / максимально возможное заявление / компьют / критерии успеха И остановки
- Выбор одной карточки; выбор и критерии замораживаются до каких-либо результатов

**День 3–5 — репродукция (наш фирменный ход)**
- Воспроизвести наименьший осмысленный результат из якорной статьи своим кодом
  (аналог нашей репродукции Шварцшильда: сначала докажи, что лаборатория не врёт)
- Числа — в интервальной арифметике, сверка с бумагой

**День 6–7 — систематическое ослабление предположений**
- По одному ослаблять предположения результата → что выживает, что ломается
- Итог недели 1: **карта предположений** + все кандидаты в контрпримеры со статусами

**Неделя 2–3 — доказательство и формализация**
- Лучшую находку — в аналитическое доказательство → в Lean
- Радар новизны по базам → если ново, оформление

**Каждая веха:** карточка на andreiplk.github.io + короткий отчёт с числами.

## 6. Результаты недели 1 (честная вилка)

- **Минимум (приемлемо):** чистая репродукция + ранее не задокументированная карта
  выживших/сломанных ослаблений → ПУБЛИЧНЫЙ АРТЕФАКТ (репо + портфолио); решение «статья
  ли это» принимается отдельно и позже, не автоматически
- **Хорошо:** сильная новая гипотеза с исчерпывающей численной поддержкой и ясной дырой
- **Отлично:** проверенный контрпример / граница / лемма → настоящий результат
- Запрещено: изготавливать «новизну» под дедлайн

## 7. Известные риски (заявлены заранее)

1. **Порог знаний поля — элитный.** Лечится: репродукция прежде творчества, 4 замка,
   интервальная арифметика, Lean
2. **Lean-формализация физики может упереться в пробелы Mathlib** — тогда честный статус
   останавливается на ANALYTICALLY_PROVED, это фиксируется
3. **Переоткрытие известного** — лечится радаром новизны до любых заявлений
4. **arXiv-эндорсмент не решён** — публикация идёт через Zenodo DOI + портфолио, arXiv позже
5. Оценки времени — прогноз, не обещание; kill-критерии в каждой карточке

## 8. Вопросы, на которые внешний проверяющий может ответить полезнее всего

1. Достаточны ли 4 замка против «правдоподобно-но-неверно» в этом поле?
2. Правильные ли якорные статьи для входа, или есть более «нижняя» точка входа?
3. Реалистична ли неделя 1, или репродукцию стоит растянуть и убрать ослабления в неделю 2?
